# RootSign v0.4.0: the release the docs site found

RootSign now has developer docs at **[docs.getprovidex.com](https://docs.getprovidex.com)**,
and every code sample and command output on them runs in CI. Writing them meant
running every claim the way a user would, and that turned up the bugs this
release fixes: two security fixes, three ways records could be lost, and a set
of errors that now fail clearly instead of strangely.

The minor version moves because several behaviours change. Read **Upgrading**
before you upgrade a PostgreSQL deployment or a script that reads exit codes.

## Upgrading

1. **PostgreSQL: run `rootsign-admin init`.** Migration 0006 adds a column that
   keeps each decision's `reasoning_depth`. `init` is idempotent.
2. **`rootsign verify` has a new exit code, `3`: nothing was verified.** An
   unknown session ID, a missing, unreadable or empty file, a usage error, or a
   database it cannot use. In 0.3.1 an unknown session ID reported `VALID` (exit
   `0`) and a database outage exited `1`, the `TAMPERED` code. A script that
   treats "not 0" as "tampered" should now treat `1` as tampered, `2` as
   incomplete and `3` as "check the command or the store".
3. **Some failures raise RootSign errors instead of raw ones.**

   | Situation | 0.3.1 | 0.4.0 |
   | --- | --- | --- |
   | `rootsign.session()` cannot open (unwritable folder, database down, the store refuses the open) | `PermissionError` / `OSError`, or the body ran and every record was refused | `RecordPersistenceError`; the body does not run |
   | A held call's pending or approval record cannot be written | `RuntimeError`, or on JSONL the approved tool ran anyway | `HiTLPersistenceError`; the tool does not run |
   | `register_agent()` for a name and environment already registered | `IntegrityError` | `ValueError` naming the existing agent ID |
   | `wrap_tools()` / `wrap_crewai_tools()` given something that is not a tool | `AttributeError` | `TypeError` naming the item |
   | `rootsign.init()` with agent fields outside the registry's limits, on JSONL | accepted | `ValueError` |
   | `require_approval=True` on the cloud transport, or with your own `LocalIngestClient` transaction | an `OSError`, or a wait that ended in `ActionNotFoundError` | `HiTLUnsupportedBackendError` |

   All are `RootSignError` subclasses except `ValueError` and `TypeError`.
4. **Positional arguments are now redacted.** A payload that carried PII in a
   positional argument hashes differently than it did under 0.3.1, because the
   hash is taken over the redacted payload. Records already stored are
   unaffected. Sessions recorded on 0.3.1 or earlier may hold PII from
   positional calls.
5. **Extras.** `autogen` is removed (it installed nothing RootSign used), and
   the floors are what CI tests: `langgraph>=0.2`, `crewai>=0.95`, `mcp>=1.22`.
6. **Supported versions.** Under [SECURITY.md](https://github.com/Providex-AI/rootsign/blob/main/SECURITY.md), only the
   latest minor is supported, so this release moves support to 0.4.x.

## Security and privacy

- **Positional PII was stored unredacted (#68).** Redaction rules matched only
  keyword arguments, so `send("alice@example.com")` kept the address while
  `send(email=...)` redacted it. Rules now match positional arguments by
  parameter name. `FinancialPIIConfig` and `HealthcarePIIConfig` accept
  `extra_rules`.
- **A held tool could run with no approval record (#77).** On the JSONL
  backend, a tool held with `require_approval=True` ran after approval even
  when the approval record could not be written. It now raises
  `HiTLPersistenceError` and does not run.
- The `init --reset` confirmation prompt no longer prints the database
  password (#73).
- `rootsign export --redact-previews` also withholds a decision's
  `alternatives_considered` (#92).

## Records that were lost

- **Buffered PostgreSQL sessions lost their last actions (#88).** With
  `ROOTSIGN_BUFFERED=true` on PostgreSQL, the end of a session could be lost
  without an error, and the session still verified `VALID`, because a cut
  tail is invisible to the chain. A write now waits for one already in
  progress.
- **The default cloud URL lost every record (#97).** A URL that answers 404
  with no ingest endpoint, which is what the default URL does while the hosted
  service is not live, now spools records instead of losing them.
- A record the store refuses is logged at `WARNING`, one line per record
  (#96). It was visible only with debug logging.

## Verification, export and the CLIs

- `rootsign verify` exit code `3` (#66, #71), as in Upgrading. Both CLIs print
  one line instead of a traceback when the database cannot be used.
- `rootsign-admin start-db` keeps its data in a Docker volume named
  `rootsign_pgdata`, so removing the container keeps the data (#72).
- `rootsign-admin sync` reports an unreachable endpoint as `FAILED`, not
  `REJECTED` (#74).
- The inline approval prompt reads the first word: `yes` approves with no
  note. It used to record the note `es` (#69).
- **Evidence bundles:** each `DECISION` carries its `reasoning_depth` (#111);
  a JSONL bundle names the agent from `agents.jsonl` in the same data folder,
  and both backends say the identity is outside the hash chain (#112);
  `report.html` fits a phone screen (#107); a cleanly synced session exported
  from a copied spool tree keeps its `sync-receipt.json`, and a synced file is
  paired with its own receipt (#52). The bundle format stays `1.0`; every
  addition is additive.

## SDK

- All `ROOTSIGN_` settings are read when `rootsign.init()` runs (#76, #89).
  Decision capture settings set in code after `import rootsign` used to be
  ignored, and the session's client re-read the rest when the session opened.
- `ctx.record_decision()` checks a decision the same way on every backend: an
  invalid one is not recorded and logs one warning (#90).
- PostgreSQL keeps each decision's `reasoning_depth` (#91, migration 0006).
- `ROOTSIGN_BACKEND=local` shows its deprecation warning by default (#76).
- The new errors in Upgrading: #83, #84, #85, #101, #102, #103.

## Cloud transport (preview)

- A session without `agent_id` raises a `ValueError` naming
  `rootsign.session(agent_id=...)` (#93).
- Without `ROOTSIGN_API_KEY`, records go straight to the spool with one warning
  naming the missing key, and no requests are made (#94).
- `require_approval=True` raises `HiTLUnsupportedBackendError` before anything
  is sent (#95).

## Integrations

- **The MCP proxy works with real streamable-HTTP MCP servers (#64).** It
  answered every request with 406.
- The extras' floors and the CI matrix agree (#61, #110). CI had named
  versions it never installed; each line is now checked against the version
  that actually installed. Tested lines: LangGraph 0.2.x, 0.6.x and 1.x;
  CrewAI 0.95.x, 0.203.x and 1.x; `mcp` 1.22.x and the newest 1.x.
- The `autogen` extra is removed; AutoGen support is planned for v1.0 (#60).

## Docs

- **[docs.getprovidex.com](https://docs.getprovidex.com):** a quickstart,
  integration pages for LangGraph, CrewAI, MCP and any Python function, task
  guides, a reference for the Python API, both CLIs, configuration, errors and
  formats, and a changelog. Tests run the pages' samples and compare their
  output blocks with what RootSign prints.
- The README is now the pitch, the quickstart and a map of the docs, with
  absolute links so it reads correctly on PyPI.
- The ingest specification lives on the docs site:
  [reference/ingest-spec-v1](https://docs.getprovidex.com/reference/ingest-spec-v1).
- Cross-implementation sync-receipt vectors and a dependency-free verifier are
  published under `tests/fixtures/sync-receipt/v1.1/` (#52).

## Not in this release

- **The session seal.** A cut tail still verifies `VALID` unless you keep a
  record count or the bundle's manifest hash outside the store.
  [ADR-016](https://github.com/Providex-AI/rootsign/pull/113) proposes a seal
  on `SESSION_CLOSE` that closes this gap; it is under review.
- **The hosted ingest service.** The cloud transport and its spool ship, as a
  preview, against the published spec.
